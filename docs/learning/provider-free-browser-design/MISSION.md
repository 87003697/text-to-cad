# Mission: Judge and guide the provider-free browser redesign

## Why
Learn to distinguish a deep-module redesign from file splitting by comparing a
historical browser-executor fallback with the current Development runtime and
the long-term Formal decision.

## Success looks like
- Explain where the external seam and internal seams belong.
- Compare competing interfaces by Depth, Leverage, Locality, and deletion test.
- Identify why the historical fallback was superseded before implementation.
- Keep Development behavior, historical design evidence, and Formal authority
  separate when reviewing a new proposal.

## Constraints
- Label the historical fallback and current runtime explicitly.
- Keep each lesson short and tied to an actual code or test decision.
- Preserve public render and evidence behavior while learning.

## Out of scope
- A general object-oriented programming course.
- A complete Linux namespace or mount-syscall tutorial.
- Product implementation, integration, or CVM execution during the lesson.
